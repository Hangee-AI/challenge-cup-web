# 部署说明（给队友看）

线上地址：**https://yinlu.pages.dev**（Cloudflare Pages，项目名 `yinlu`）

## 一句话结论

**这个项目「push 到 GitHub」不会自动上线。** 线上页面是手动部署上去的，
所以推了代码、本地能看到，网页上却还是旧的。

历史上能自动部署的是 Surge（`guoguan.surge.sh`），但 Surge 上传大 bundle（3.9–4.5MB）会被截断导致白屏，
已经在 `ffa2bda` 里停用了那条 workflow。此后线上一直靠手动 `wrangler pages deploy`。

## 改完代码后，怎么让线上更新

### 方案 C（推荐：配一次，以后 push 自动上线）

1. 打开 https://dash.cloudflare.com → 右上 My Profile → **API Tokens** → **Create Token**
2. 选模板 **Edit Cloudflare Workers**（至少要有 `Cloudflare Pages: Edit`）→ 创建 → 复制 token（只显示一次）
3. 打开 GitHub 仓库 `Hangee-AI/challenge-cup-web` → Settings → Secrets and variables → **Actions** → **New repository secret**
   - `CLOUDFLARE_API_TOKEN` = 上面复制的 token
   - `CLOUDFLARE_ACCOUNT_ID` = `eaf45aa1a7fa0673c2fe0d9bd44771e0`
4. 完事。以后任何 push 到 `main`，`.github/workflows/deploy-pages.yml` 会自动
   构建 + 发布，1 分钟上线。没配 token 时这个 workflow 会自动跳过（不会报红）。

### 方案 A（临时手动部署，需要登录过 Cloudflare 的电脑）

```powershell
cd C:\Users\18007\Documents\challenge-cup-web
git pull                      # 先拉到最新
node tools/cf-build.js        # 100+ 个 js 打成一个 bundle，输出 dist-cf/
npx wrangler pages deploy dist-cf --project-name yinlu --branch main
```

跑完会打印 `https://xxxx.yinlu.pages.dev` 预览地址，正式地址 https://yinlu.pages.dev 同步更新。

> Windows 上 `npx` 报「在此系统上禁止运行脚本」时，用 `npx.cmd` 代替，或
> `powershell -ExecutionPolicy Bypass -Command "npx wrangler pages deploy dist-cf --project-name yinlu --branch main"`。

### 方案 B（云面板点「重新部署」）

目前**不可靠**：项目是用 wrangler 直接上传的，面板里没有连 GitHub，
点重新部署只会重发上次的产物，不会构建新代码。

## 为什么不能各人各自部署

- 部署需要 Cloudflare 账号权限，多人部署容易互相覆盖；
- 每次 bundle 4.5MB 左右，上传 7–40 秒，谁最后部署谁说了算；
- 本地没 `git pull` 就部署，会把别人的改动盖回去。

**统一约定：改完 → push → 由 Actions 自动部署（方案 C）**。

---

## 上线后怎么确认真的更新了

```powershell
curl.exe -s https://yinlu.pages.dev/ | Select-String "课程视频"     # 看你改的文案
curl.exe -s https://yinlu.pages.dev/api/stats                        # 接口是否活着
curl.exe -s https://yinlu.pages.dev/ | Select-String "bundle.js?v="  # bundle 版本号是否变了
```

浏览器里还是旧版就 `Ctrl+F5` 强刷（bundle 带版本号，通常不用手动清缓存）。
