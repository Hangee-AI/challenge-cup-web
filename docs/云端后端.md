# 云端后端（Deno Deploy）部署说明

目标：**你的电脑关机，别人也能注册 / 登录 / 打卡 / 看板 / 用学习搭子**。

现在线上分两层：

| 层 | 在哪 | 负责 |
|---|---|---|
| 静态站 | Surge（`https://guoguan.surge.sh`） | 页面、样式、脚本、题库、离线判题 |
| 接口 | **Deno Deploy**（本文） | 账号、会话、打卡、看板、点亮、学习搭子 |

接口代码在 **`deno/main.ts`**（一个文件，不需要 npm 依赖，数据存 Deno KV）。

---

## 一、先在本地跑通（可选，但建议）

需要 Deno 2（[deno.com](https://deno.com) 下载，或 `npm i -g deno`）。

```powershell
cd C:\Users\18007\Documents\challenge-cup-web
$env:PORT="3212"
$env:LLM_PROVIDER="openrouter"
$env:OPENROUTER_API_KEY="sk-or-v1-xxxx"     # 不填也能启动，只是学习搭子走本地兜底
deno run --unstable-kv --allow-net --allow-env --allow-read --allow-write .\deno\main.ts
```

> `--unstable-kv` 只有本地 Deno 需要；Deno Deploy 上 KV 是直接可用的。

自测（PowerShell 里 curl 传 JSON 要用文件，别用 `-d '{"a":1}'`，引号会被吃掉）：

```powershell
$body = '{"prefix":"NCU","sid":"9110126060","password":"abc123456"}'
[IO.File]::WriteAllText("$env:TEMP\r.json", $body)
curl.exe -s -X POST http://127.0.0.1:3212/api/auth/register -H "Content-Type: application/json" --data-binary "@$env:TEMP\r.json"
curl.exe -s http://127.0.0.1:3212/api/ping
```

已实测通过的接口：注册 / 登录 / 忘记密码重置 / 改密码 / 退出 / me / 打卡（首次与重复）/ 看板 / 点亮（去重）/ chat/status / CORS 预检。

## 二、部署到 Deno Deploy（免费，不要银行卡）

1. 打开 <https://dash.deno.com>，用 **GitHub 账号登录**（就是 `Hangee-AI` 那个）。
2. 点 **New Project** → **Deploy from GitHub** → 选仓库 `Hangee-AI/challenge-cup-web`。
   - 如果看不到仓库，点 GitHub 授权页里的 **Grant access** 把仓库勾上。
3. 项目配置：
   - **Entry point**：`deno/main.ts`
   - **Install / Build**：留空（不需要）
   - **KV**：项目设置里 **Provision / Attach KV database**，名字随便（如 `yinlu-kv`），确保运行时能 `Deno.openKv()`。
4. **Environment Variables**（项目 Settings → Environment Variables）：

   | Key | Value | 说明 |
   |---|---|---|
   | `LLM_PROVIDER` | `openrouter` | 学习搭子用 OpenRouter |
   | `OPENROUTER_API_KEY` | `sk-or-v1-...` | 你的 OpenRouter Key（只在服务器上） |
   | `CHAT_PER_IP_HOUR` | `40` | 每 IP 每小时最大问答数（可选） |
   | `CHAT_DAILY_CAP` | `800` | 全站每天上限（可选） |
   | `CHAT_REQUIRE_LOGIN` | `1` | 只允许登录用户用（可选） |

5. 点 **Deploy**，等 1 分钟左右，会拿到一个地址，形如：

   ```
   https://yinlu.deno.dev
   ```

6. 验证：

   ```powershell
   curl.exe -s https://yinlu.deno.dev/api/ping
   # {"ok":true,"app":"yinlu","runtime":"deno","ts":...}
   ```

## 三、把静态站指到新后端

打开 `js/config.js`，把地址换成你的 Deno 域名：

```js
window.YL_API_BASE = 'https://yinlu.deno.dev';
```

提交推送（`git push origin main`），GitHub Actions 会自动重新发布 Surge。
1–2 分钟后打开 <https://guoguan.surge.sh>：

- 首页三张看板有真实数字（不再是「—」）
- 个人中心能注册 / 登录 / 忘记密码 / 改密码
- 右下角小引能回答（不再是「只连着本地」）

> 想临时测别的后端，可以不改代码，在浏览器控制台执行
> `localStorage.setItem('yl_api_base','http://127.0.0.1:3212')` 后刷新。

## 四、和旧版（server/ + 隧道）的区别

| | `server/`（Express + JSON 文件） | `deno/main.ts`（Deno + KV） |
|---|---|---|
| 跑在哪 | 你的电脑 / 一台常开的机器 | Deno 云端 |
| 电脑关机 | 别人用不了 | 照常可用 |
| 地址 | 隧道地址，重启就变 | 固定 `https://xxx.deno.dev` |
| 判题 | 有 `/api/run`、`/api/judge`（本地 gcc） | 没有，判题在前端离线完成 |
| 密码哈希 | scrypt | PBKDF2-SHA256（10 万次） |
| 数据 | `server/data/db.json` | Deno KV |

**账号不互通**：两边的密码哈希算法不同，用户在 Deno 版需要重新注册一次（或用「忘记密码」重置）。

## 五、常见问题

**Q：`Deno.openKv is not a function` / KV 报错？**
本地漏了 `--unstable-kv`；云端是没给项目绑 KV 数据库，去项目 Settings → KV 里 Provision 一个。

**Q：注册报 409「这个学号已经注册过了」？**
Deno KV 里已有该学号。要清空测试数据，本地删掉 `.deno-kv` 目录（Deno 2 的本地 KV 落在项目或用户目录，可用 `deno run --unstable-kv -A -` 里 `Deno.openKv()` 后 `kv.delete` 精确删）；线上 KV 目前没有一键清空，测试期建议用随机学号。

**Q：CORS 报错？**
`deno/main.ts` 里 `ALLOWED_ORIGINS` 允许了 `guoguan.surge.sh`、`*.surge.sh`、`*.deno.dev` 和 localhost。换域名要把它加进去。

**Q：学习搭子说「还没配置模型 Key」？**
没设 `OPENROUTER_API_KEY`。设置后**不需要重启代码**？——需要重新 Deploy 一次让新环境变量生效（Deno Deploy 里改完变量会自动重新部署）。

**Q：想换回 DeepSeek 官方？**
把 `LLM_PROVIDER` 改 `deepseek`，`DEEPSEEK_API_KEY` 填 Key 即可（模型 `deepseek-chat`）。
