# 团队协作指南

> 仓库地址：`git@github.com:Hangee-AI/challenge-cup-web.git`
> 本文写给一起改这个网页的同学，照着做一遍就能开始干活。

---

## 一、第一次配置（每台电脑只做一次）

### 1. 装 Git

- 下载地址：https://git-scm.com/download/win
- 一路默认安装即可

装完打开「Git Bash」（开始菜单里搜），输入下面这行确认：

```bash
git --version
```

### 2. 配置名字和邮箱

```bash
git config --global user.name "你的名字"
git config --global user.email "你的邮箱"
```

> 名字会写进提交记录，以后答辩展示"谁做了什么"靠它，**别随便填**。

### 3. 生成 SSH 密钥

```bash
ssh-keygen -t ed25519 -C "你的邮箱"
```

一路回车（不用设密码）。然后把公钥复制出来：

```bash
cat ~/.ssh/id_ed25519.pub
```

把输出的**一整行**发给负责人，由负责人加进 GitHub 仓库。

### 4. 配置 GitHub 的 443 端口（重要）

国内网络经常连不上 `github.com:443`，但 `ssh.github.com:443` 是通的。先编辑：

```bash
code ~/.ssh/config
```

> 没有 `code` 命令就用记事本打开：`notepad ~/.ssh/config`

写入以下内容并保存：

```
Host github.com
  HostName ssh.github.com
  Port 443
  User git
  IdentityFile ~/.ssh/id_ed25519
  IdentitiesOnly yes
```

测试一下：

```bash
ssh -T git@github.com
```

看到 `Hi 你的用户名! You've successfully authenticated` 就成功了。

### 5. 把仓库拉下来

```bash
cd 你想放项目的文件夹
git clone git@github.com:Hangee-AI/challenge-cup-web.git
cd challenge-cup-web
```

## 二、每天怎么干活

**每天开工前先拉取**：

```bash
git pull
```

**改完文件后提交并推送**：

```bash
git add .
git commit -m "改了什么都写清楚，比如：题库第 2 关补充 3 道题"
git push
```

**四句话口诀**：先 `pull`，再改，`add` + `commit`，最后 `push`。

---

## 三、怎么看不冲突（最重要的规矩）

### 按「文件」分工，不要按「功能」分工

| 谁 | 负责文件 | 别人别动 |
|---|---|---|
| 同学 A | `js/data.js`（题库） | ✅ |
| 同学 B | `css/style.css`（样式） | ✅ |
| 同学 C | `js/app.js`（逻辑） | ✅ |

同一个文件两个人同时改，就一定会冲突。**要么分文件，要么错开时间改。**

### 分支策略（简单版）

- `main`：随时能演示的版本，**只有确认能用才合并进来**
- `dev`：日常开发都提交到这里

作业流程：

```bash
git checkout dev        # 切到开发分支
# ... 改代码 ...
git add .
git commit -m "说明"
git push
```

确认没问题后，再由负责人合并到 `main`。

## 四、常见问题

| 问题 | 解决 |
|---|---|
| `Repository not found` | SSH 密钥没加到仓库 / 还没被加为协作者，找负责人 |
| `Connection was reset` / 超时 | 检查第 4 步的 SSH 443 配置有没有生效 |
| `git pull` 报冲突 | 别慌，打开冲突文件，找 `<<<<<<<` 和 `>>>>>>>`，留下你要的内容，删掉标记，然后 `git add . && git commit` |
| 改错了想回滚 | `git log` 找到之前的提交号，`git reset --hard 提交号`（**会丢改动，慎用**） |
| 不小心提交了不该提的文件 | 先把它加进 `.gitignore`，再 `git rm --cached 文件名` |

## 五、提交记录的作用

**`git log` 里的每一次提交，都是"这个作品是我们自己做的"的证明材料。**

所以：

- 提交说明写清楚（不要只写 "update"）
- 每天都要有提交，不要攒到最后一天一次性提交
- **不要**在答辩前一晚把别人整份代码拷进来改成自己的名字——提交时间戳和逐步演进过程骗不了人
